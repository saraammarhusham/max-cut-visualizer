What Is the Max-Cut Problem?

Given an undirected graph G = (V, E) and an integer k, the Max-Cut decision problem asks: does there exist a partition of the vertices into two disjoint sets S and V∖S such that at least k edges have one endpoint in each set?

An edge that crosses the partition boundary is called a cut edge. The number of such edges is the cut size. We want to maximize this cut size — hence the name Max-Cut.

📐 Formal Problem Statement
Input: Undirected graph G = (V, E), integer k ≥ 0.
Question: Is there a partition (S, V∖S) such that |{(u,v) ∈ E : u ∈ S, v ∈ V∖S}| ≥ k?
Optimization version: Find a partition that maximizes the number of crossing edges.

Why Max-Cut Matters in the Real World

Max-Cut is not just a theoretical puzzle — it models real engineering and scientific problems where you need to split things into two groups while maximizing the connections between them.

⚡

VLSI Circuit Layout

Partitioning circuit components across chips minimizes cross-chip wiring, reducing signal delay and manufacturing cost.

🧲

Statistical Physics

Max-Cut models the ground-state energy of Ising spin-glass systems — a fundamental model in condensed matter physics.

🌐

Network Partitioning

Maximizing edges between clusters finds community structure in social and communication networks.

📡

Frequency Assignment

Assigning frequencies to transmitters using Max-Cut-style partitioning avoids interference between nearby stations.

🔬

Protein Folding

Computational biology uses graph cuts to model interactions between protein residue groups across fold boundaries.

🎮

Quantum Computing

The Quantum Approximate Optimization Algorithm (QAOA) was designed specifically to target Max-Cut on near-term quantum devices.

Section 2

Overview

Build your foundation: cuts, partitions, cut edges, and why Max-Cut becomes exponentially hard.

The Graph — Starting Point

Everything in Max-Cut starts with a graph. A graph G = (V, E) consists of:

V — Vertices

A set of nodes (also called vertices or points). Each vertex represents something — a circuit component, a network node, a variable. We label them A, B, C, … or 0, 1, 2, …

E — Edges

A set of connections between pairs of vertices. An edge (u, v) means u and v are connected. In Max-Cut, edges are undirected — they have no direction.

G = (V, E)

The graph as a whole. We will partition its vertices into two groups and count how many edges cross the boundary between the groups.

What Is a Cut?

A cut is simply a way of splitting all the vertices into exactly two groups. Every vertex must go into exactly one group — no vertex is left out, and no vertex can be in both groups.

📐 Formal Definition
A cut is a partition of the vertex set V into two non-empty, disjoint sets:

Set S — the "blue side"
Set T = V ∖ S — the "red side" (all vertices not in S)

Every vertex belongs to exactly one side.
✂️ Cut Edge vs Internal Edge
Cut edge: an edge whose two endpoints are on different sides of the partition. It "crosses" the cut boundary.

Internal edge: an edge whose two endpoints are on the same side. It stays within one group and does not count toward the cut size.

Cut size = the total number of cut edges for a given partition.

Illustrated Example

Vertices in blue belong to Set S. Vertices in red belong to T. Green edges cross the cut; grey edges do not.

Set S (blue) Set T (red) Cut edge Internal edge

Decision Version vs. Optimization Version

⚖️ Decision Version — Is it ≥ k?

Input: Graph G = (V, E), integer k.

Question: Does there exist a partition with cut size ≥ k?

Answer is simply YES or NO. This is the version that is proven NP-complete.

Example: "Does a cut of size ≥ 3 exist in this graph?" → YES/NO
🎯 Optimization Version — Maximize it

Input: Graph G = (V, E).

Goal: Find the partition with the largest possible cut size.

This is NP-hard — no polynomial-time algorithm is known. Algorithms either search exhaustively (exact) or approximate (fast but not always optimal).

Example: "What is the maximum cut size in this graph?" → 4

Why Does the Problem Grow So Hard?

The key insight: each vertex has exactly two choices — go into Set S or Set T. With n vertices, the total number of distinct partitions is 2ⁿ.

⚠️ Exponential Growth

Every added vertex doubles the number of partitions to check. This is why exact algorithms are only practical for very small graphs.

Common Mistakes to Avoid

⛔ Common Errors
  • Confusing cut edges with total edges: Only edges that cross the S–T boundary count. Edges within S or within T are internal and do not contribute to the cut size.
  • Thinking local search always finds the optimum: Local search only guarantees a local maximum — no single flip can improve it. The true global maximum may be higher.
  • Forgetting that swapping S and T gives the same cut: The partition {A, B} vs {C, D} produces the exact same cut as {C, D} vs {A, B}. This is why there are 2ⁿ⁻¹ distinct cuts, not 2ⁿ.
  • Assuming NP means "not possible": NP means "verifiable in polynomial time." NP-complete problems are hard to solve optimally, but given a solution you can check it quickly.
  • Mixing up decision and optimization: The NP-complete result applies to the decision version (is cut ≥ k?). The optimization version (find the maximum cut) is NP-hard.
💡 Key Takeaway
Max-Cut is easy to verify but hard to optimize exactly.
Given any partition, you can check its cut size in O(|E|) — just count crossing edges. But finding the best partition requires, in the worst case, checking exponentially many options. This gap between easy verification and hard optimization is the essence of NP-completeness.

Key Concept Summary

Cut
A partition of V into two non-empty sets S and T = V∖S.
Cut Edge
An edge with one endpoint in S and the other in T.
Internal Edge
An edge with both endpoints on the same side — does not count.
Cut Size
The number of cut edges for a given partition.
Local Optimum
A partition that cannot be improved by moving any single vertex.
Global Optimum
The partition with the largest cut size over all possible partitions.
Section 3

NP-Completeness Proof

Why is Max-Cut so hard? We prove it step-by-step — with visuals, plain English, and zero hand-waving.

⚠️ Important Note
This section presents a conceptual teaching visualization of the NP-completeness proof. It is pedagogically structured and simplifies some steps for clarity. It does not constitute a full formal proof as would appear in a theoretical CS journal. Simplifications are labeled where they occur.

First: What Does "NP-Complete" Actually Mean?

Before we dive into the proof, let's make sure these terms make intuitive sense:

🔍
NP

Problems where, if someone gives you a solution, you can check it quickly (in polynomial time). You might not be able to find the solution quickly, but you can verify it.

Example: Given a partition, counting cut edges takes O(|E|) — fast!
🏔️
NP-Hard

Problems that are at least as hard as every other problem in NP. If you could solve it quickly, you could solve all NP problems quickly.

No known polynomial-time algorithm exists for any NP-hard problem.
⭐
NP-Complete

The hardest problems in NP. They are both in NP (checkable fast) and NP-hard (as hard as anything). Max-Cut is one of these.

NP-Complete = NP ∩ NP-Hard

Proof Roadmap — The Big Picture

To prove MAX-CUT is NP-complete, we need to do exactly two things:

①
Show MAX-CUT ∈ NP

Prove that given any partition, we can verify whether it achieves cut size ≥ k in polynomial time.

→ Easy: just count crossing edges in O(|E|)
②
Show MAX-CUT is NP-Hard

Show that a known NP-complete problem (NAE-3-SAT) can be transformed into MAX-CUT in polynomial time.

→ We build a reduction: NAE-3-SAT ≤ₚ MAX-CUT
To prove: MAX-CUT is NP-complete
Step 1. Show MAX-CUT ∈ NP → verify a solution in O(|E|) time Step 2. Choose source problem: NAE-3-SAT (known NP-complete) Step 3. Build reduction f: NAE-3-SAT → MAX-CUT in polynomial time Step 4. Forward: YES in NAE-3-SAT ⟹ YES in MAX-CUT Step 5. Backward: YES in MAX-CUT ⟹ YES in NAE-3-SAT Conclusion: MAX-CUT is NP-hard; since it is also in NP → NP-complete ∎

Step 1 — Proving MAX-CUT is in NP

A problem is in NP if we can verify a proposed solution quickly. Here's what that looks like for Max-Cut:

1
The Certificate (Proof Witness)

Someone claims they have a great partition. Their "proof" (certificate) is just:

A list: which set each vertex goes into
Example: A→S, B→T, C→S, D→T
Length: n bits — polynomial in input size ✓
2
The Verifier (Checking the Proof)

To check the certificate, we simply:

1. Scan every edge (u, v)
2. Check if u and v are in different sets
3. Count how many edges cross
4. If count ≥ k → ACCEPT, else REJECT
Time: O(|E|) — clearly polynomial ✓
✅ Conclusion: MAX-CUT ∈ NP
We have a certificate of length n (polynomial) and a verifier running in O(|E|) time (polynomial). Therefore MAX-CUT ∈ NP. ✓

💡 Why This Works
If MAX-CUT were easy (polynomial-time solvable), we could just translate any NAE-3-SAT instance to a graph and solve it instantly — solving NAE-3-SAT too. But NAE-3-SAT is NP-complete, so no such fast solver exists (unless P=NP). Therefore MAX-CUT must also be hard.

Step 2 — The Source Problem: NAE-3-SAT

Not-All-Equal 3-SAT (NAE-3-SAT) — Plain English

Imagine you have a list of rules, each containing exactly 3 things. The rule is satisfied if the 3 things are not all the same — at least one must be different from the others.

✓ NAE Satisfied
Clause (A=TRUE, B=FALSE, C=TRUE)
Not all equal → GOOD ✓

Clause (x=FALSE, y=FALSE, z=TRUE)
Not all equal → GOOD ✓
✗ NAE Violated
Clause (A=TRUE, B=TRUE, C=TRUE)
All TRUE = all equal → BAD ✗

Clause (x=FALSE, y=FALSE, z=FALSE)
All FALSE = all equal → BAD ✗
🔑 Key Symmetry — Why We Choose NAE-3-SAT
NAE-3-SAT has a beautiful symmetry: if an assignment satisfies it, flipping every variable (TRUE↔FALSE) also satisfies it. This mirrors the symmetry of cuts: swapping S and T gives the same cut size. This shared symmetry makes the reduction work perfectly.

Step 3 — Building the Reduction (The Construction)

Given any NAE-3-SAT formula φ with variables x₁, …, xₙ and clauses C₁, …, Cₘ, we build a graph G as follows:

① Vertices
For each variable xᵢ, create two vertices:
xᵢ (represents xᵢ = TRUE)
x̄ᵢ (represents xᵢ = FALSE)

Add a variable edge between xᵢ and x̄ᵢ — this forces them to opposite sides.
Total vertices: up to 2n variable vertices
② Clause Triangles
For each clause (ℓ₁ ∨ ℓ₂ ∨ ℓ₃), create a triangle:
Add edge between ℓ₁ and ℓ₂
Add edge between ℓ₂ and ℓ₃
Add edge between ℓ₁ and ℓ₃

Set threshold: k = n + 2m
Total edges: n variable edges + 3m clause edges

🔺 The Clause Triangle Gadget — Interactive

This is the heart of the reduction. Each clause (ℓ₁ ∨ ℓ₂ ∨ ℓ₃) becomes a triangle. Click each scenario to see why it works:

Analysis
📐 The Key Insight About Triangles
A triangle contributes 2 cut edges when its vertices are split (some in S, some in T) — i.e., when the clause is NAE-satisfied.
A triangle contributes 0 or 1 cut edges when all vertices are on the same side — i.e., when NAE is violated.

The threshold k = n + 2m is chosen so that we can only reach it if every clause triangle contributes 2 (all NAE satisfied) AND every variable edge crosses (all variables assigned consistently).

① What "Forward Direction" means

The claim: If the NAE-3-SAT formula has a satisfying assignment, then the graph we built has a cut of size at least k.

In other words: SAT YES → MAX-CUT YES. A working assignment for the formula automatically produces a good cut in the graph.

② The Example Assignment

Take clause (x₁ ∨ ¬x₂ ∨ x₃) with assignment:

x₁ = TRUE → Set S ¬x₂ = FALSE → Set T x₃ = FALSE → Set T

TRUE literals → Set S (blue). FALSE literals → Set T (red). The triangle is split across both sides → 2 cut edges.

This clause contributes 2 cut edges. ✓

③ Why k = n + 2m

k is not discovered — we choose it. It is the "perfect score" that can only be achieved when every part of the graph contributes its maximum:

n variable edges × 1 cut edge each = n
m clause triangles × 2 cut edges each = 2m
Total: k = n + 2mk is the threshold we set when building the Max-Cut instance from NAE-3-SAT. A cut of size ≥ k is only achievable when every variable edge crosses AND every clause triangle contributes 2 cut edges.

If any triangle contributes fewer than 2, the total falls below k — which means that clause was NAE-violated.

④ Why this proves equivalence

The forward direction shows: NAE-SAT YES → MAX-CUT YES.

The backward direction shows: MAX-CUT YES → NAE-SAT YES.

Together they prove: φ is NAE-satisfiable if and only if G has a cut ≥ k. The two problems have identical YES/NO answers — the reduction perfectly preserves the answer.

① What "Backward Direction" means

The claim: If the graph has a cut of size at least k, then the original NAE-3-SAT formula must have a satisfying assignment.

In other words: MAX-CUT YES → SAT YES. A good cut in the graph automatically gives us a working assignment for the formula.

② Reading the cut back as an assignment

Start with the graph cut that achieves ≥ k cut edges. We read the partition back:

In Set S → literal is TRUE In Set T → literal is FALSE

Since the triangle has 2 cut edges, its vertices must be split — some in S, some in T. That means the clause has at least one TRUE and at least one FALSE literal.

Therefore the NAE conditionNAE (Not-All-Equal): at least one literal in the clause is TRUE and at least one is FALSE. This is exactly what the triangle with 2 cut edges guarantees. is satisfied. ✓

③ Why the triangle forces a split

To reach k = n + 2m, every clause triangle needs to contribute exactly 2 cut edges.

A triangle contributes 2 cut edges only when its vertices are on different sides of the partition — i.e., not all on one side.

If any triangle were all on one side, it contributes 0 cut edges → total falls below k → contradiction with our assumption. So every triangle must be split.

Split triangle ↔ NAE-satisfied clause ✓

④ Why this proves equivalence

The backward direction shows: MAX-CUT YES → NAE-SAT YES.

The forward direction shows: NAE-SAT YES → MAX-CUT YES.

Together: the two problems always have the same answer. This is exactly what a valid reduction requires — the answer is preserved in both directions.

Step 4 — Forward Direction (NAE-SAT → MAX-CUT)

Claim: If φ has a NAE-satisfying assignment → G has a cut of size ≥ k
1
Translate the assignment to a partition: Put vertex xᵢ in Set S if xᵢ = TRUE, in Set T if xᵢ = FALSE. Put x̄ᵢ on the opposite side (since x̄ᵢ is the negation of xᵢ).
2
Variable edges always cross: xᵢ and x̄ᵢ always have opposite truth values, so they always land on opposite sides → each of the n variable edges is a cut edge. That gives us n cut edges.
3
Clause triangles contribute 2 each: Since the assignment is NAE-satisfying, every clause has at least one TRUE and one FALSE literal. Their triangle vertices sit on different sides → each triangle contributes 2 cut edges. That gives us 2m cut edges.
✓
Total cut size ≥ n + 2m = k. Forward direction proved. ✓

Step 5 — Backward Direction (MAX-CUT → NAE-SAT)

Claim: If G has a cut of size ≥ k → φ has a NAE-satisfying assignment
1
Translate partition back to an assignment: Set xᵢ = TRUE if the xᵢ-vertex is in S, and xᵢ = FALSE if it is in T.
2
Variable edges force consistency: To achieve cut ≥ k = n + 2m, we need all n variable edges to cross (contribute 1 each). This means xᵢ and x̄ᵢ must be on opposite sides — which means the assignment is consistent (xᵢ and its negation have opposite truth values). ✓
3
Clause triangles force NAE: We need the remaining 2m cut edges from the m clause triangles (2 each). A triangle only contributes 2 cut edges if its vertices are on different sides — meaning the clause has literals of both truth values. That is exactly the NAE condition. ✓
!
Contradiction argument: If any clause triangle were all on one side (NAE violated), it contributes ≤ 1 cut edge instead of 2. This reduces the total below k = n + 2m. But we assumed the cut is ≥ k — contradiction! So every clause must be NAE-satisfied. ✓
✓
Every clause is NAE-satisfied → φ has a NAE-satisfying assignment. Backward direction proved. ✓

The certificate is a partition of the vertices — a binary string of length n (n bits saying which set each vertex goes into). Its length is O(n), which is polynomial. The verifier scans all edges and counts crossing ones in O(|E|) time. Since both certificate length and verification time are polynomial, MAX-CUT ∈ NP.

This mirrors the symmetry of cuts — swapping S and T gives the same cut size. The triangle gadget directly encodes the NAE condition as a local cut-size requirement. Regular 3-SAT lacks this symmetry, making the reduction harder to construct cleanly.

Since the threshold k requires 2 cut edges per triangle, a monochromatic triangle makes reaching k impossible — exactly corresponding to an unsatisfied NAE clause.
Yes. Goemans and Williamson (1995) gave a 0.878-approximation algorithm using semidefinite programming. Under the Unique Games Conjecture (Khot, 2002), approximating MAX-CUT better than ≈0.878 is NP-hard, making GW essentially optimal. NP-complete means NP-hard AND in NP (i.e., has a polynomial-time verifier). MAX-CUT is NP-complete because it is both hard (NP-hard) and verifiable quickly (in NP). Section 4

Brute Force Exact Algorithm

Exhaustive search over all 2n partitions. Exact but exponential.

Algorithm Idea

The brute-force approach enumerates every possible partition of the vertex set and returns the one with the maximum cut size. With n vertices, there are 2n subsets represented as bitmasks from 0 to 2n−1.

Pseudocode

function BruteForceMaxCut(G = (V, E)): n ← |V| // number of vertices bestCut ← 0 // best cut size found so far bestMask ← 0 // bitmask encoding best partition for mask ← 0 to 2ⁿ − 1 do // iterate all subsets cutSize ← 0 // cut edges for this mask for each edge (u, v) ∈ E do // evaluate every edge if bit(mask, u) ≠ bit(mask, v) then // u and v on different sides? cutSize ← cutSize + 1 // this edge crosses the cut if cutSize > bestCut then // new best found bestCut ← cutSize bestMask ← mask return bestMask, bestCut // optimal partition and cut size
📊 Time Complexity
The outer loop runs 2n times. The inner edge-evaluation loop runs O(|E|) per iteration. Total: O(2n · |E|).
✅ Why Use Brute Force?
Brute force is exact — it always finds the true optimum. For small graphs (n ≤ 15), it is practical and serves as a gold standard.

Section 5

Greedy Local Search

A practical polynomial-time heuristic with a guaranteed ½-approximation ratio.

Algorithm Idea

Local search begins with an arbitrary partition and iteratively improves it by making small local changes — specifically, flipping a single vertex from one side to the other. If this flip increases the cut size, we perform it. We repeat until no single flip can improve the cut.

📐 Gain Formula
When vertex v is in side S with dS(v) same-side neighbors and dT(v) other-side neighbors:
Gain from flip = dS(v) − dT(v). Flip if gain > 0.

Pseudocode

function LocalSearchMaxCut(G = (V, E)): S ← random subset of V // initial partition improved ← true while improved do improved ← false for each vertex v ∈ V do // consider every vertex dS ← |{neighbors of v in same side as v}| dT ← |{neighbors of v in other side}| gain ← dS − dT // gain from flipping v if gain > 0 then // flip improves cut? flip v to the other side improved ← true // keep scanning return S, cutSize(S) // local maximum
📌 Key Theorem
The local-search algorithm always returns a cut of size ≥ OPT / 2. At a local maximum, every vertex v satisfies: number of neighbors on opposite side ≥ number on same side. Summing over all edges, at least half of all edges cross the cut.

🛑 Why Local Search Stops Here

Why Local Search Guarantees at Least a ½-Approximation

Local search does not always find the perfect answer — but it comes with a provable guarantee: the cut it finds is always at least half as large as the best possible cut. This section explains exactly why, step by step.

📌 The Guarantee — Formally

Local search for MAX-CUT always produces a cut whose size is at least half of the optimal cut.

cut(Local) ≥ ½ · OPT

Where OPT = the size of the maximum possible cut (what brute force finds). This is an unconditional worst-case guarantee — it holds for every graph, no exceptions.

½
approximation ratio

① Simple Intuition — Build Your Understanding First
A
Cut edges connect vertices on opposite sides. Every edge in the graph is either a cut edge (endpoints on different sides) or an internal edge (endpoints on the same side). A bigger cut means more edges crossing.
B
When can we flip a vertex to improve the cut? Suppose vertex v is in Set S. Every edge from v to another S-vertex is internal. Every edge from v to a T-vertex is a cut edge. If we move v to T, the internal edges become cut edges and the cut edges become internal. The net change (gain) is: gain = dS(v) − dT(v). If gain > 0, flipping helps.
C
When local search stops, no vertex can be flipped. This means for every vertex v, gain ≤ 0 — i.e., dT(v) ≥ dS(v). Every vertex already has at least as many neighbors across the cut as on its own side.

④ The Core Proof — Step by Step
Step 1 — Start from the local optimality condition

At a local optimum, for every vertex v:  dT(v) ≥ dS(v).
This means: the number of edges from v crossing the cut ≥ the number of edges from v staying on the same side.

Step 2 — Sum over all vertices

Add up the condition dT(v) ≥ dS(v) for all vertices v:

Σ dT(v)  ≥  Σ dS(v)
(sum over all vertices v)

The left side counts each cut edge twice (once from each of its two endpoints). The right side counts each internal edge twice (once from each endpoint).

2 × |cut edges|  ≥  2 × |internal edges|
⟹  |cut|  ≥  |internal|
Step 3 — Use the fact that all edges are either cut or internal

Every edge is either a cut edge or an internal edge — nothing else. So:

|E|  =  |cut| + |internal|
Since |cut| ≥ |internal|, we get:
|E|  =  |cut| + |internal|  ≤  |cut| + |cut|  =  2 × |cut|
⟹  |cut| ≥ |E| / 2
Step 4 — Connect to the optimal solution

The optimal cut cannot cross more edges than the total number of edges in the graph:

OPT  ≤  |E|
(you can't cut more edges than exist)
✅ Final Conclusion — Chain Everything Together
cut(Local)  ≥  |E| / 2  ≥  OPT / 2
▲ from Step 3             ▲ from Step 4
cut(Local) ≥ ½ · OPT ✓

⭐ A+ Takeaway

Local search does not guarantee the optimal solution, but it guarantees that the solution is never worse than half of the optimal. This is a provable approximation bound based on the fact that no single vertex flip can improve the solution — and that condition alone is enough to ensure the cut is at least half of all edges.

📎 Advanced Note (optional)

This ½ guarantee also holds for a simple randomized algorithm that assigns each vertex to Set S or Set T independently and uniformly at random (each with probability ½). In expectation, exactly half of all edges cross the cut — giving expected cut size = |E|/2 ≥ OPT/2. Both the greedy local search and this random assignment achieve the same ½-approximation ratio, though by very different arguments.

Part 2 — Local Search Walkthrough

Local search starts from an arbitrary partition and iteratively flips vertices to improve the cut. It stops when no single flip helps.

Initial Partition

S = {A, B}, T = {C, D}

Computing the initial cut: A–C ✓, B–C ✓, B–D ✓ → cut size = 3.

We choose this starting point for illustration. A different starting point could lead to a different final answer.

Iteration 1 — Test Vertex A (currently in S)

A's neighbors: B (in S) and C (in T).

Same-side neighbors: B → dS(A) = 1  |  Other-side neighbors: C → dT(A) = 1

Gain = dS(A) − dT(A) = 1 − 1 = 0. No improvement. Skip A.

Iteration 1 — Test Vertex B (currently in S)

B's neighbors: A (in S), C (in T), D (in T).

Same-side: A → dS(B) = 1  |  Other-side: C, D → dT(B) = 2

Gain = 1 − 2 = −1 < 0. Flipping B would hurt the cut. Skip B.

Iteration 1 — Test Vertex C (currently in T)

C's neighbors: A (in S), B (in S), D (in T).

Same-side: D → dT(C) = 1  |  Other-side: A, B → dS(C) = 2

Gain = dT(C) − dS(C) = 1 − 2 = −1 < 0. Skip C.

💡 Gain Formula Reminder
Gain for vertex v = (neighbors on same side as v) − (neighbors on opposite side). If positive → flip improves the cut. If zero or negative → don't flip.
Iteration 1 — Test Vertex D (currently in T)

D's neighbors: B (in S), C (in T).

Same-side: C → 1  |  Other-side: B → 1

Gain = 1 − 1 = 0. No improvement. Skip D.

End of first pass. No vertex was flipped — improved = false. Local search stops.

⚠️ Local Search Result
Final cut = 3. Local search stopped at S = {A, B}, T = {C, D} with cut size 3.
The global optimum is 4 (found by brute force). Local search missed the optimum because no single vertex flip from this starting point improves the cut — even though a better partition exists.
This perfectly illustrates why local search is an approximation algorithm, not an exact one.

Local Optimum vs Global Optimum

🏠 Local Optimum

A partition where no single vertex can be moved to improve the cut size. Local search always ends at a local optimum.

Example above: S = {A,B}, T = {C,D}, cut = 3. No single flip helps — this is a local optimum.

Local optima depend on the starting partition. A different start might lead to a different local optimum — possibly the global one.

🏆 Global Optimum

The partition with the largest possible cut size over all partitions. Only brute force guarantees finding it.

Example above: S = {A,C}, T = {B,D}, cut = 4. This is the global optimum — no other partition beats it.

The global optimum is unique in value (though multiple partitions may tie for it). Brute force certifies it by checking everything.

Viva & Q&A Preparation

Likely instructor questions with clear, concise model answers. Study these before your presentation.

Given an undirected graph G = (V, E) and integer k, the Max-Cut decision problem asks: does there exist a partition of V into two sets S and V∖S such that the number of edges with one endpoint in each set is at least k? The optimization version asks for the partition that maximizes this count. Max-Cut is NP-complete (decision version) and NP-hard (optimization version).
A problem is in NP if a proposed YES-solution can be verified in polynomial time. For Max-Cut, the certificate is a partition of the vertices (n bits — polynomial length). The verifier scans all edges and counts those that cross the partition boundary, which takes O(|E|) time — clearly polynomial. Since we have a polynomial-length certificate and a polynomial-time verifier, Max-Cut ∈ NP.
The certificate is an explicit partition: a binary string of length n where bit i = 1 means vertex i goes into Set S, and bit i = 0 means it goes into Set T. This certificate has length n (polynomial). Given this certificate, the verifier counts crossing edges in O(|E|) time and accepts if the count is ≥ k.
The verifier receives the graph G = (V, E), the integer k, and the certificate (the partition). It then scans every edge (u, v) in E and checks whether u and v are in different partition sides. It counts all such crossing edges. If the total count is ≥ k, it accepts (YES). Otherwise it rejects. The entire process takes O(|E|) time.
With n vertices, there are 2ⁿ possible subsets (each vertex independently goes into S or T). Brute force checks all of them. For each subset, it evaluates all |E| edges to count the cut size. Total time: O(2ⁿ · |E|). This is exponential in n — doubling with every additional vertex. For n = 50, 2⁵⁰ ≈ 10¹⁵ partitions, which would take millions of years to check even at 10⁹ checks per second.
Local search starts from an arbitrary partition and repeatedly considers flipping each vertex to the opposite side. For each vertex v, it computes the gain = (same-side neighbors) − (other-side neighbors). If gain > 0, it flips v immediately (without backtracking or exploring further). This is greedy because it always takes the locally improving move without considering future consequences. It repeats passes over all vertices until no flip is beneficial.
Each accepted flip strictly increases the cut size by at least 1 (since gain > 0 means cut increases by exactly gain ≥ 1). The cut size is a non-negative integer bounded above by |E| (the total number of edges). Since the cut size strictly increases with each flip and is bounded, at most |E| improving flips can occur. Therefore local search terminates in O(|E|) flips.
No — local search only guarantees finding a local optimum, not the global optimum. A local optimum is a partition where no single vertex flip improves the cut. However, a better partition may exist that requires moving two or more vertices simultaneously — and local search never considers such multi-vertex moves. On many practical graphs it does find the optimum, but this is not guaranteed. The starting partition also matters: different starting points can lead to different local optima.
The ½-approximation guarantee means local search always returns a cut of size ≥ OPT/2, where OPT is the true maximum cut size. This is an unconditional worst-case guarantee — no matter what graph you give it, the answer is always at least half the optimum. Proof sketch: at a local optimum, for every vertex v, the number of neighbors on the other side is at least the number on the same side (otherwise we'd flip). Summing this over all vertices gives 2·|CUT| ≥ |E| − |CUT|, so |CUT| ≥ |E|/3 — actually with a tighter argument we get |CUT| ≥ |E|/2 ≥ OPT/2.
NAE-3-SAT (Not-All-Equal 3-SAT) is used because it shares a key symmetry with Max-Cut: if an assignment satisfies NAE-3-SAT, then flipping all variables (TRUE↔FALSE) also satisfies it — just as swapping S and T gives the same cut size. This symmetry makes the reduction work cleanly. The clause triangle gadget directly encodes the NAE condition: a triangle contributes 2 cut edges iff its vertices are split across both sides of the partition, which corresponds exactly to the clause being NAE-satisfied.
NP-hard means "at least as hard as every problem in NP" — a problem X is NP-hard if every NP problem can be reduced to X in polynomial time. NP-complete means NP-hard AND in NP (i.e., the problem also has a polynomial-time verifier). Max-Cut is NP-complete because: (1) it is in NP (polynomial verifier exists) and (2) it is NP-hard (NAE-3-SAT ≤ₚ Max-Cut). The optimization version of Max-Cut is NP-hard but not NP-complete, since optimization problems are not decision problems and thus not "in NP" in the standard sense.
Yes — Goemans and Williamson (1995) gave a randomized algorithm based on semidefinite programming (SDP) that achieves a 0.878-approximation ratio. This is significantly better than the ½ guarantee of local search. Under the Unique Games Conjecture (Khot, 2002), 0.878 is essentially optimal — no polynomial-time algorithm can achieve a better ratio unless the conjecture is false. The Goemans-Williamson algorithm is not implemented in this tool as it requires advanced mathematics beyond the scope of this course.
