What Is the Max-Cut Problem?

Given an undirected graph G = (V, E) and an integer k, the Max-Cut decision problem asks: does there exist a partition of the vertices into two disjoint sets S and V∖S such that at least k edges have one endpoint in each set?

An edge that crosses the partition boundary is called a cut edge. The number of such edges is the cut size. We want to maximize this cut size — hence the name Max-Cut.

📐 Formal Problem Statement
Input: Undirected graph G = (V, E), integer k ≥ 0.
Question: Is there a partition (S, V∖S) such that |{(u,v) ∈ E : u ∈ S, v ∈ V∖S}| ≥ k?
Optimization version: Find a partition that maximizes the number of crossing edges.

Why Does Max-Cut Matter?

⚡

VLSI Circuit Layout

Partitioning circuit components across chips minimizes cross-chip wiring, reducing signal delay and manufacturing cost.

🧲

Statistical Physics

Max-Cut models the ground state energy of Ising spin-glass systems — a fundamental model in condensed matter physics.

🌐

Network Clustering

Maximizing edges between clusters captures community structure in social and communication networks.

📡

Frequency Assignment

Assigning frequencies to transmitters with Max-Cut-style partitioning avoids interference between nearby stations.

🔬

Protein Folding

Computational biology uses graph cuts to model interactions between protein residue groups across fold boundaries.

🎮

Quantum Computing

The Quantum Approximate Optimization Algorithm (QAOA) was designed specifically to target Max-Cut on near-term quantum devices.

Section 2

Overview

Core concepts: cuts, cut size, decision vs. optimization, and why Max-Cut is hard.

What Is a Cut?

Given an undirected graph G = (V, E), a cut is a partition of the vertex set V into two non-empty, disjoint sets S and T = V∖S. Every vertex belongs to exactly one side of the partition.

Definition: Cut Edge
An edge (u, v) ∈ E is a cut edge (also called a crossing edge) if and only if one endpoint lies in S and the other lies in T. Edges where both endpoints are on the same side do not contribute to the cut size.

Decision Version vs. Optimization Version

⚖️ Decision Version

MAX-CUT (Decision)

Input: Graph G = (V,E), integer k.

Question: Is there a partition (S, V∖S) with cut size ≥ k?

This is the version that is proven NP-complete. We either say YES or NO.

🎯 Optimization Version

MAX-CUT (Optimization)

Input: Graph G = (V,E).

Goal: Find the partition that maximizes cut size.

This is what algorithms try to solve in practice. It is NP-hard — no polynomial-time algorithm is known.

Why Is Max-Cut Hard?

The core difficulty is combinatorial explosion. With n vertices, there are 2n possible subsets S of V. Even discounting the trivial partition (S = V or S = ∅), we have 2n − 2 partitions to consider. Since each partition into S and V∖S is counted twice (swapping sides gives the same cut), there are (2n − 2) / 2 = 2n-1 − 1 distinct cuts.

NP-Completeness Proof

Reduction from NAE-3-SAT to MAX-CUT with verification structure.

⚠️ Important Note
This section presents a conceptual teaching visualization of the NP-completeness proof. It is pedagogically structured and simplifies some steps for clarity. It does not constitute a full formal proof as would appear in a theoretical CS journal. Simplifications are labeled where they occur.

Proof Structure Overview

To prove: MAX-CUT is NP-complete
Step 1. Show MAX-CUT ∈ NP Step 2. Choose a known NP-complete problem (NAE-3-SAT) Step 3. Construct a polynomial-time reduction f: NAE-3-SAT → MAX-CUT Step 4. Prove forward direction: YES in NAE-3-SAT ⟹ YES in MAX-CUT Step 5. Prove backward direction: YES in MAX-CUT ⟹ YES in NAE-3-SAT Conclusion: MAX-CUT is NP-hard; since it is also in NP, it is NP-complete ∎

↓ polynomial-time construction

Both answers agree
φ is NAE-satisfiable ⟺ G has a cut of size ≥ k

Step 1 — MAX-CUT is in NP

1

Certificate

A proposed certificate (witness) is a partition: a labeling of each vertex as either S or T = V∖S.

2

Verifier

Given the certificate, scan all edges. Count those with one endpoint in S and one in T. If this count ≥ k, accept; otherwise reject. This takes O(|E|) time — clearly polynomial in the input size.

✅ Conclusion: In NP
Since a valid partition of size n bits serves as a polynomial-length certificate, and the verifier runs in O(|E|) ⊆ O(n2) time, MAX-CUT ∈ NP.

Step 2 — Source NP-Complete Problem: NAE-3-SAT

Not-All-Equal 3-SAT (NAE-3-SAT)

Input: A Boolean formula in conjunctive normal form (CNF) where each clause contains exactly 3 literals (possibly negated variables).

Question: Is there a truth assignment such that in every clause, the three literals are not all equal? (i.e., at least one is TRUE and at least one is FALSE — unlike standard 3-SAT where we just need one TRUE.)

NAE-3-SAT is known to be NP-complete (Schaefer's theorem, 1978). It has a useful symmetry property: if assignment α satisfies it, so does its complement ᾱ (flipping all bits). This symmetry mirrors the symmetry of cuts (swapping S and T gives the same cut size).

Step 3 — Reduction Construction

Given an NAE-3-SAT formula φ with variables x1, …, xn and clauses C1, …, Cm, construct graph G = (V, E) as follows:

Vertex Construction
  • Create one vertex xi and one vertex x̄i for each variable xi.
  • For each clause Cj = (ℓ1 ∨ ℓ2 ∨ ℓ3), create a triangle: add edges between each pair of the three literal vertices.
  • Total vertices: up to 2n variable vertices + 3m clause vertices (depending on construction variant).
Simplification Note
A full rigorous construction also adds "consistency" edges between complementary literal vertices (xi and x̄i) to enforce that they land on opposite sides of the cut. The core idea is captured here.
Edge Construction
  • Variable edges: Add an edge between xi and x̄i for each variable. These edges enforce that a variable and its negation are on opposite sides of any maximum cut.
  • Clause triangles: For each clause (ℓ1, ℓ2, ℓ3), add edges (ℓ1–ℓ2), (ℓ2–ℓ3), (ℓ1–ℓ3).
  • Threshold: Set k = n + 2m. A cut achieves this threshold iff the assignment is NAE-satisfying.

Clause Triangle Gadget

Each clause (ℓ1 ∨ ℓ2 ∨ ℓ3) becomes a triangle. The NAE condition means NOT all three literals have the same truth value — equivalently, NOT all three triangle vertices are on the same side. A triangle with vertices on both sides contributes 2 cut edges; a monochromatic triangle contributes 0 or 1. The threshold k ensures we can only achieve it when all triangles satisfy NAE.

Step 4 — Forward Direction

Claim: If φ has a NAE-satisfying assignment α, then G has a cut of size ≥ k = n + 2m.

Argument: Assign each literal vertex to side S if the literal is TRUE under α, and to side T if FALSE. By the NAE condition, each clause has at least one TRUE and one FALSE literal, so its triangle has vertices on both sides — contributing at least 2 cut edges. Each variable edge (xi, x̄i) crosses because xi and x̄i always have opposite truth values, so they land on opposite sides. Total cut size ≥ n (variable edges) + 2m (clause triangle edges) = k. ✓

Step 5 — Backward Direction

Claim: If G has a cut of size ≥ k, then φ has a NAE-satisfying assignment.

Argument: Given an optimal cut (S, T) achieving ≥ k edges, define: set xi = TRUE if the xi-vertex is in S, and xi = FALSE otherwise. The variable edges force xi and x̄i onto opposite sides (otherwise those n edges don't cross, making k unreachable). For each clause, to contribute 2 cut edges to the triangle, it must have vertices on both sides — meaning the clause is NAE-satisfied. If any clause were all-same-side, its triangle contributes only ≤ 1 edge instead of 2, reducing the total below k. Contradiction. ✓

Step 6 — Polynomiality of the Reduction

✅ Polynomial Time
The reduction creates O(n + m) vertices and O(n + m) edges, and the threshold k = n + 2m is computed in O(1). The entire construction runs in O(n + m) time — clearly polynomial in the size of φ. ✓

Conclusion

📌 NP-Completeness
MAX-CUT ∈ NP (polynomial verifier exists) AND NAE-3-SAT ≤p MAX-CUT (polynomial reduction shown). Since NAE-3-SAT is NP-complete, MAX-CUT is NP-hard. Therefore, MAX-CUT is NP-complete. ∎

Instructor Q&A — Expandable

The certificate is a partition of the vertices: a labeling of each vertex as belonging to S or T. Its length is O(n) bits, which is polynomial. The verifier scans all edges and counts crossing ones in O(|E|) time.
NAE-3-SAT has a natural symmetry: negating all literals in a satisfying assignment produces another satisfying assignment. This mirrors the symmetry of cuts (swapping S and T gives the same cut size). The triangle gadget directly encodes the NAE condition as a local cut-size requirement.
If all three literals of a clause land on the same side of the partition, the three triangle edges are all within one partition side — none of them cross the cut. This means that clause contributes 0 (or at best 1 if exactly one vertex differs) instead of the 2 needed to meet the threshold k. This failure corresponds exactly to a clause that is NAE-violated.
Yes. It is known (assuming the Unique Games Conjecture, Khot 2002) that approximating Max-Cut better than approximately 0.878 is NP-hard. The Goemans-Williamson semidefinite programming algorithm achieves exactly this 0.878 ratio, making it essentially optimal under the conjecture. The simple local-search algorithm shown in this tool achieves only the weaker ½-approximation guarantee.
NP-hard means "at least as hard as every problem in NP" — every NP problem reduces to it in polynomial time. NP-complete means NP-hard AND in NP. MAX-CUT is NP-complete (it is both hard and has a polynomial verifier). The optimization version is NP-hard but not technically NP-complete (since optimization problems are not decision problems and thus not "in NP" by the standard definition).
Section 4

Brute Force Exact Algorithm

Exhaustive search over all 2n partitions. Exact but exponential.

Algorithm Idea

The brute-force approach is conceptually simple: enumerate every possible partition of the vertex set and return the one with the maximum cut size. With n vertices, there are 2n subsets. We represent each subset as a bitmask from 0 to 2n−1. Bit i is 1 if vertex i belongs to set S, and 0 if it belongs to T = V∖S.

⚠️ Common Mistake
Students sometimes think we can check only "half" the partitions because swapping S and T gives the same cut. While true, this does not change the asymptotic complexity — we still need Θ(2n) evaluations in the worst case.

Pseudocode

function BruteForceMaxCut(G = (V, E)): n ← |V| // number of vertices bestCut ← 0 // best cut size found so far bestMask ← 0 // bitmask encoding best partition for mask ← 0 to 2ⁿ − 1 do // iterate all subsets cutSize ← 0 // cut edges for this mask for each edge (u, v) ∈ E do // evaluate every edge if bit(mask, u) ≠ bit(mask, v) then // u and v on different sides? cutSize ← cutSize + 1 // this edge crosses the cut if cutSize > bestCut then // new best found bestCut ← cutSize bestMask ← mask return bestMask, bestCut // optimal partition and cut size
📊 Time Complexity
The outer loop runs 2n times. The inner edge-evaluation loop runs O(|E|) per iteration. Total: O(2n · |E|). This is exponential in n — infeasible for graphs with more than ~20–25 vertices in practice.
✅ Why Use Brute Force?
Brute force is exact — it always finds the true optimum. For small graphs (n ≤ 15), it is practical and serves as a gold standard against which to compare approximate solutions.

Why Brute Force Becomes Impractical

⛔ Exam / Viva Tip
If asked "why can't we just try all partitions?", give a concrete example: for n = 50, 250 ≈ 1015 partitions. Even a modern computer checking 109 per second would take over 11 days for n = 50 alone — and the count doubles with every added vertex.
Section 5

Greedy Local Search

A practical polynomial-time heuristic with a guaranteed ½-approximation ratio.

Algorithm Idea

Instead of checking all 2n partitions, local search begins with an arbitrary partition and iteratively improves it by making small local changes. The move we consider is: flip a single vertex from one side to the other. If this flip increases the cut size, we perform it. We repeat until no single flip can improve the cut.

The resulting partition is a local maximum — it cannot be improved by any single-vertex move. It is not necessarily the global maximum.

📐 Gain Formula
When vertex v is in side S with dS(v) neighbors also in S and dT(v) neighbors in T:
Current contribution to cut = dT(v) (edges crossing between v and T).
After flipping v to T: contribution = dS(v) (now edges to S neighbors cross).
Gain from flip = dS(v) − dT(v). Flip if gain > 0.

Pseudocode

function LocalSearchMaxCut(G = (V, E)): S ← random subset of V // initial partition improved ← true while improved do improved ← false for each vertex v ∈ V do // consider every vertex dS ← |{neighbors of v in same side as v}| dT ← |{neighbors of v in other side}| gain ← dS − dT // gain from flipping v if gain > 0 then // flip improves cut? flip v to the other side improved ← true // keep scanning return S, cutSize(S) // local maximum

The ½-Approximation Guarantee

📌 Key Theorem
Theorem: The local-search algorithm above always returns a cut of size ≥ OPT / 2, where OPT is the size of the maximum cut.

Informal argument: At a local maximum, every vertex v satisfies: the number of its neighbors on the opposite side ≥ the number on the same side (otherwise we could improve by flipping). This means every edge is at least as likely to be a cut edge as not. Summing over all edges, at least half of all edges cross the cut.
Simple Formal Sketch

At a local maximum for vertex v: dT(v) ≥ dS(v), where dT(v) = cut neighbors, dS(v) = same-side neighbors.

Summing over all v ∈ S: Σv∈S dT(v) ≥ Σv∈S dS(v).

Left side counts each cut edge once (from the S endpoint). Right side counts internal edges within S twice. So: CUT ≥ |ES|, where ES = internal edges of S. Similarly for T. Adding both: 2·CUT ≥ |ES| + |ET| = |E| − CUT. Therefore: 3·CUT ≥ |E| — actually we get CUT ≥ |E|/2 ≥ OPT/2 since OPT ≤ |E|. ✓

What This Means in Practice

A ½-approximation means we are guaranteed to find a cut at least half as good as the best possible. This is an unconditional guarantee — regardless of the graph structure.

In practice, local search often performs much better than ½ — sometimes finding the true optimum. But the guarantee only promises ½.

⚠️ Common Mistake
Do not claim local search always finds the optimum. It can and does get stuck at local maxima that are not global maxima. See the preset examples for demonstration.

Local Search Walkthrough (From a Specific Start)

Initial partition: S = {A, B, C} (blue), T = {D, E} (red). We now run local search.

Initial State

S = {A, B, C}, T = {D, E}.

Cut edges: A–? (B in S, no cut), A–? (C in S, no cut), B–C (both in S, no cut), B–D (B∈S, D∈T → cut), C–E (C∈S, E∈T → cut), D–E (both in T, no cut).

Initial cut size = 2.

Iteration 1 — Check Vertex A

A is in S. Neighbors: B (in S), C (in S). Same-side neighbors: 2. Other-side neighbors: 0.

Gain from flipping A to T: dS(A) − dT(A) = 2 − 0 = +2. Gain > 0 → Flip A to T.

New partition: S = {B, C}, T = {A, D, E}. Cut: B–D, C–E, A–B, A–C → cut size = 4.

Iteration 1 — Check Vertex B (after flipping A)

B is in S. Neighbors: A (in T), C (in S), D (in T). Same-side: C (1). Other-side: A, D (2).

Gain from flipping B: dS(B) − dT(B) = 1 − 2 = −1 < 0. Do not flip.

Iteration 1 — Check Vertex C

C is in S. Neighbors: A (in T), B (in S), E (in T). Same-side: B (1). Other-side: A, E (2).

Gain: 1 − 2 = −1 < 0. Do not flip.

Iteration 1 — Check Vertices D and E

D is in T. Neighbors: B (S), E (T). Same-side: E (1). Other-side: B (1). Gain = 1 − 1 = 0. Do not flip.

E is in T. Neighbors: C (S), D (T). Same-side: D (1). Other-side: C (1). Gain = 0. Do not flip.

No improvement found in this pass — but we did flip A earlier so improved = true. Start another pass.

Iteration 2 — Full pass, no improvements

Current: S = {B, C}, T = {A, D, E}. Cut size = 4.

Check all vertices: no vertex gives gain > 0. Terminate.

✅ Local Search Result
Final partition: S = {B, C}, T = {A, D, E}.
Local search cut size = 4 — matches the brute-force optimum of 4.
Total flips made: 1 (vertex A). Total steps: ~10 vertex checks.
⚠️ Why May Local Search Miss the Optimum?
In this example, local search happened to find the optimal cut. This is not guaranteed in general. If the initial partition had been S = {A, B, D}, T = {C, E}, local search might have converged to a different local maximum with cut size 3, missing the optimal 4. The outcome depends on the starting partition and the order in which vertices are considered.
📌 Key Takeaway
  • Brute force examined 32 partitions to certify that 4 is optimal.
  • Local search made 1 flip and examined ~10 vertices to reach a local maximum of 4.
  • Both reached the same answer here, but local search gives no guarantee of being optimal — only that the answer is ≥ OPT/2.

Cut edgeAn edge with exactly one endpoint in each partition side.
Cut sizeThe number of cut edges for a given partition.
Maximum cutA partition that maximizes the number of cut edges over all possible partitions.
Local maximumA partition where no single vertex flip improves the cut size.
NPThe class of decision problems solvable in polynomial time by a nondeterministic Turing machine, or equivalently, problems with polynomial-time verifiable certificates.
NP-hardA problem at least as hard as every problem in NP (every NP problem reduces to it in polynomial time).
NP-completeA problem that is both in NP and NP-hard.
Polynomial reductionA function f computable in polynomial time such that x ∈ A iff f(x) ∈ B; used to show hardness.
NAE-3-SATNot-All-Equal 3-SAT: given a 3-CNF formula, is there an assignment where each clause has at least one TRUE and at least one FALSE literal?
Approximation ratioThe guaranteed worst-case ratio of the algorithm's output to the true optimum.
½-approximationAn algorithm guaranteed to output a solution of value at least OPT/2.
BitmaskAn integer whose binary representation encodes a subset (bit i = 1 iff element i is in the subset).
GadgetA small sub-graph used in a reduction to enforce a specific logical constraint.

Viva Preparation — Quick Answers

Given an undirected graph G = (V, E) and integer k, does there exist a partition (S, V∖S) such that the number of edges with exactly one endpoint in S is at least k?
A certificate is a partition of the vertices (a binary string of length n). The verifier counts crossing edges in O(|E|) time — polynomial. So Max-Cut ∈ NP.
We reduce from NAE-3-SAT, which is NP-complete. It is chosen because both problems share a useful symmetry: complementing all variable assignments in NAE-3-SAT gives another valid solution, mirroring the symmetry of cuts (swapping S and T).
For each variable, create a pair of complementary literal vertices. For each clause (ℓ₁ ∨ ℓ₂ ∨ ℓ₃), add a triangle on those three literal vertices. Set k = n + 2m. A NAE-satisfying assignment maps to a partition achieving k cut edges (n variable edges + 2 per satisfied triangle), and vice versa.
The outer loop runs exactly 2ⁿ times (a finite number). For each subset, the cut size is computed correctly by scanning all edges. The maximum over all evaluated cut sizes is the global maximum. Correctness: every partition is examined, so the global maximum cannot be missed.
Each improving flip strictly increases the cut size by at least 1. The cut size is a non-negative integer bounded above by |E|. Therefore at most |E| improving flips can occur, and the algorithm terminates in O(|E|) flips total.
At a local maximum, for every vertex v: d_T(v) ≥ d_S(v) (otherwise we could flip v to improve). Summing over all vertices on both sides: the number of cut edges ≥ the number of internal edges on each side. This gives 2·|CUT| ≥ |E| − |CUT|, so 3·|CUT| ≥ |E|, and in particular |CUT| ≥ |E|/2 ≥ OPT/2 since OPT ≤ |E|.

Presentation Reminders

📣 What to Say in Your Presentation
  • Start by stating the problem clearly and formally.
  • Emphasize that Max-Cut is NP-complete — both in NP and NP-hard.
  • When explaining the reduction, say: "We show NAE-3-SAT ≤p Max-Cut using a triangle gadget for each clause."
  • For brute force: "It is exact but exponential — O(2ⁿ · |E|)."
  • For local search: "It is polynomial and practical, with a proven ½-approximation guarantee."
  • Be ready to explain why the algorithm terminates (finite improving flips).
  • Know the ½-approximation proof sketch.
